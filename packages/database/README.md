# packages/database

All SQL for the `SmartUniversityDB` MySQL database. Every file starts with
`USE SmartUniversityDB;`, and `schema/schema.sql` drops and recreates the
database, so loading it wipes any existing copy.

| Folder     | Contents                                                              |
| ---------- | --------------------------------------------------------------------- |
| `schema/`  | Core structure: `schema.sql` (database + 12 core tables), `enterprise_core.sql` (assets, document requests, workflow history) |
| `modules/` | Feature DDL layered on the core: extra tables plus the views, stored procedures and triggers |
| `seed/`    | `INSERT` data at several scales                                       |
| `queries/` | `verify.sql` — read-only checks of the views and procedures           |

## Load order

`scripts/setup_db.py` (run with `npm run db:setup` from the repository root)
loads exactly these files, in this order:

1. `schema/schema.sql`
2. `schema/enterprise_core.sql`
3. `modules/advanced_features.sql`
4. `modules/addons.sql`
5. `modules/transport.sql`
6. `modules/academic_pro.sql`
7. `seed/data.sql`
8. `seed/data_addons.sql`
9. `seed/data_massive_v6.sql` — before the triggers, so the bulk load stays fast
10. `modules/analytics.sql` — views, procedures, triggers
11. `modules/alumni_career.sql` — uses procedures from `analytics.sql`
12. `modules/audit_system.sql` — last, so seeding is not audited
13. `queries/verify.sql`

The result is 35 tables, 8 views, 10 triggers and 4 stored procedures, with
50,020 students, 10,510 faculty, 5 campuses and 5,000 assets.

`init_database.sql` is the same sequence as `mysql` client `SOURCE`
commands, without steps 7 and 8. SOURCE paths are relative to the client's
working directory, so run it from this folder:

```bash
cd packages/database
mysql -u root -p < init_database.sql
```

## Optional seed files

The load order above leaves the transport, alumni, placement and document
request tables empty, so those dashboard panels show nothing. To fill them,
load `seed/sample_data_v2.sql` afterwards:

```bash
mysql -u root -p < packages/database/seed/sample_data_v2.sql
```

The other seed files are not loaded by either script. They are earlier or
alternative data sets, kept for reference:

| File                              | Inserts into                                   |
| --------------------------------- | ---------------------------------------------- |
| `data_advanced.sql`               | Companies, PlacementDrives, PlacementResults, MaintenanceLogs |
| `data_expansion.sql`              | Students, Faculty, Companies (150-student expansion) |
| `data_massive_v2.sql`             | Students, Faculty, Enrollments, Books, Hostels, PlacementResults |
| `data_ultra_v5.sql`               | Departments, Students, Assets (V5.1)          |
| `data_ultra_v5_personalized.sql`  | Departments, Students, Assets (V5.1 variant)  |
| `test_assets.sql`                 | Assets (5,000 rows)                            |

## Regenerating the large data set

`seed/data_massive_v6.sql` is generated by `scripts/generate_data.py`, which
writes it in place. The generator is unseeded, so each run produces different
rows.

```bash
python scripts/generate_data.py
```
